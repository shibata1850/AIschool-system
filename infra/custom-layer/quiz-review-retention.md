# 小テスト確認待ちデータの期限切れ削除

対象は `canvas_quiz_review_candidates` の一時確認データだけです。Canvasの正式な答案・成績、在籍・退会後の正式な学習履歴、監査ログは削除しません。30日を過ぎると画面から非表示となり、このコマンドで期限切れのコピーを削除します。

本番への配備・定期実行登録・実データ削除は別作業です。適用前に担当者がパッチ・削除範囲・予定件数を確認してください。

## 配備時の順序

1. カスタム層のレビュー済みソースをビルドする。Dockerfileで `scripts/purge-quiz-reviews.ts` を `dist-scripts/purge-quiz-reviews.mjs` へ変換し、本番依存のみで実行可能にする。
2. `CANVAS_REVIEW_INSTANCE` が取り込み元と一致していることを確認する。接続には既存のアプリ用 `DATABASE_URL` を使う。管理者用DBロールは不要。
3. 削除せず件数だけを確認する。

```sh
docker compose exec -T app node dist-scripts/purge-quiz-reviews.mjs --dry-run
```

引数なしもdry-runです。表示するのは件数・DB時刻・処理種別だけで、受講者番号や得点は出力しません。

4. 本番での削除範囲が確認・承認された後、アプリの環境設定へ `QUIZ_REVIEW_RETENTION_ENABLED=true` を設定する。設定反映と再起動は通常の配備手順で行う。
5. 手動で1回実行し、終了コード・残件数・監査記録を確認する。

```sh
docker compose exec -T app node dist-scripts/purge-quiz-reviews.mjs --apply
```

6. 正常に確認できたら既存のサーバーcronへ登録する。例は毎時17分（サーバー時刻）。ファイルを置くだけでは登録されない。

```cron
17 * * * * cd ~/AIschool-system/infra/custom-layer && docker compose exec -T app node dist-scripts/purge-quiz-reviews.mjs --apply >>~/backups/quiz-review-retention.log 2>&1
```

`~/backups` は既存の運用ログ配置例。実配置、cronのタイムゾーン、ログローテーション、失敗監視を配備時に確認する。停止する場合はこのcron行を無効化し、`QUIZ_REVIEW_RETENTION_ENABLED` を無効にする。

## 制御と監査

- `--apply` と設定値 `true` の両方があるときだけ削除する。入力引数で期限・受講者・コースを指定して削除範囲を広げることはできない。
- 保存元の識別子が一致し、DBの現在時刻で `expires_at <= now()` の候補だけを対象にする。別システム由来・期限内の候補は残す。
- 1トランザクション500件まで。同じ保存元の期限切れ処理をDBの専用ロックで直列化し、同じトランザクションで削除件数・保存元・判定時刻の監査記録を追加する。監査が失敗したバッチは削除も戻る。既存のアプリ用DB権限（SELECT／INSERT／DELETE）を使い、UPDATE権限は追加しない。
- 1実行は最大20バッチ（10,000件）。バッチ間は独立して確定するため、後半の失敗で前半の完了分は戻らない。監査記録で完了を確認できる。再実行しても削除済みの候補は再処理しない。
- dry-runの件数は、その時点の見積もり。並行する取得・削除によってapply時の件数は変わる。
- 正常終了は0。設定／接続／処理失敗やロック待ちの時間切れは1。処理が完了しても上限などで期限切れが残る場合は2。非0や残件数を放置せず、次回の実行と監査を確認する。
- SQLの実行・ロック待ちは各20秒、運用コマンド全体は3分を上限にする。途中終了時も、確定済みのバッチと監査は残る。
- 毎時実行の場合、正常稼働・処理量が上限内なら非表示から次の実行まで約1時間以内で削除する。停止・エラー・大量滞留時にこの間隔を保証するものではない。
- バックアップ内のコピーは既存バックアップの保持ルールで管理する。DB削除だけでバックアップからも即座に消えるとは扱わない。
