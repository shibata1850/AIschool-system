# 講師の採用・取り下げと受講者本人の記録表示

更新：2026-09-19。実装・検証用の累積パッチ。本番反映・実受講者への表示は未実施。

## 授業での操作

1. 担当講師がCanvasのコースから起動し、分析CSVを取得して確認待ちで保存する。
2. Canvasの答案画面で、受講者、受験回、各設問の得点を確認する。CSVの作成完了だけでは最新性や内容の一致を保証しない。
3. 確認した結果のチェック欄を選び「この結果を本人表示に採用」を押す。
4. 受講者が「自分の到達度」から「講師確認済みの小テスト記録を見る」を開く。選ばれた受験回、合計、技能別得点、講師確認日時、表示期限を表示する。
5. 誤りや再確認が必要なら、講師が「本人表示を取り下げる」。受講者は次回取得・再読み込み時から当該結果が非表示になる。開いたままの画面への即時配信はない。

## 採用する結果の決め方

- コース・受講者・Canvas保存元・小テストごとに採用できるのは1結果。他の回や再採点版を採用すると置き換わる。
- 最新回・最高点を自動選択しない。講師が選んだ回として明示する。CSVや再採点の自動追跡はない。
- 未採点を含む結果は採用できない。採点済みの0点は採用可能。
- 自動照合の成功を採用済みとは扱わない。採点対象・練習用のどちらも、採用前にCanvasの答案画面で講師が確認する方式。
- 新規取得・再取込だけで採用結果を変更しない。確認欄は採用状態が変わるとリセットする。
- 古い画面や別講師からの上書きは操作番号の照合で409エラーとなる。再読み込みして現在の状態を確認する。通信エラー時も自動で操作を繰り返さない。

## 表示範囲と保持期間

これは復習用の小テスト記録。既存の出席・課題・自宅学習による到達度計算への加算や、Canvasへの成績書込みは行わない。正式な習熟度へ統合する場合は、教材と既存課題の対応・評価式・正式履歴の保持を別途確定する。

採用は確認用コピーを参照する。表示期限はコピーの保存から30日で、採用操作では延長しない。期限後は表示から外れ、既存の期限切れ処理で候補を削除すると採用状態も外部キーにより削除される。コース所属・受講者の削除時も連動する。正式な学習履歴の「在籍中＋退会後3年」方針を、この一時記録に置き換える変更ではない。

監査記録は同じトランザクションで記録する。操作した講師、日時、採用対象のハッシュ・状態・操作番号、手動確認の有無を残す。設問別得点・氏名・回答本文は監査へ複写しない。監査失敗時は採用変更も取り消す。

## 本人・担当権限の確認

- 講師操作では署名済みLTI、コースの現在の担当登録、受講者の現在の受講登録、内部IDとCanvas数値IDの一意対応、コース所属を確認する。
- 受講者APIは署名済みLTIの本人・コースを使用し、指定された受講者番号やコース番号で取得しない。クエリ付き要求は拒否する。
- 受講者側も現在のCanvas受講登録と内部ID対応を確認する。講師・ゲストによる本人用APIの利用、別人のID対応、別コース、重複したID対応は拒否する。内部IDが別のCanvas番号へ対応変更された場合、以前のCanvas番号の候補は表示しない。
- 本人APIにはCanvas番号・内部ID・講師ID・候補ハッシュ・CSV取得元情報を返さない。本人の得点と日時だけを返す。キャッシュを無効にする。
- 講師操作APIはOrigin照合、JSONのみ、実読取2KB上限。予期しない引数・確認チェックなしの採用を拒否する。

## 配備時の設定

- 追加マイグレーション：`0018_canvas_quiz_decisions`。既存候補テーブルへの参照を持つ採用状態テーブルを作成。候補や監査の権限は拡張しない。
- `QUIZ_REVIEW_PUBLICATION_ENABLED=true` のときだけ採用操作・本人表示を有効化。初期値は無効。設定を無効にすると本人表示も停止する。
- 入口：`/teacher/quiz-review`、`/achievement/quizzes`。
- API：`POST /api/teacher/quiz-review/decision`、`GET /api/quiz-results`。
- 本番マイグレーション・設定変更・再起動・実アカウント確認は別途。今回実行していない。

## 検証と残作業

隔離DBと架空Canvasで、採用→本人表示→別版への置換→取り下げ、役割・別人・別コース拒否、未採点・0点・期限切れ、同時操作、監査失敗時の取り消しを検証。最新件数は [verification.json](verification.json)。

初回ブラウザーテストは、テストのログイン切替後に講師画面へ移動せず受講者画面を再読み込みしていたため3条件で失敗。画面遷移を修正して再検証した。

最終点検で内部IDのCanvas番号が変更されたケースを追加。変更前の候補が表示される失敗をNUCのE2Eで再現し、保存済み候補のCanvas番号と署名済みセッションの番号も一致する条件を追加した。

既存の授業設定テストは同じDBで全体実行を繰り返すと、前回の架空設定を残して競合する。最終検証ではこの1件が失敗したため、隔離DB内の当該2コースの架空設定・子レコード・架空監査だけを初期化して全体を再実行した。初期化の最初の試行は外部キー制約で取り消され、子レコードを先に処理する順序へ修正した。再現確認に使うDBは毎回初期状態を用意すること。本番や実コースで同様の初期化を行わない。

残るのは本番ソースとの統合とレビュー、Dockerイメージ全体の検証、正式な習熟度計算への対応設計、実アカウント・実機・学校側の通し確認。現時点では本番への採用も、実成績の公開も行っていない。
