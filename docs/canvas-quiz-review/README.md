## 成績・表示の扱い

採用は復習用の本人表示です。正式な成績はCanvasにあり、既存の到達度の算出式（出席・課題・自宅学習）への加算やCanvasへの書込みはありません。採用は1人・1小テストにつき1結果、未採点は採用不可。確認用コピーの保存から30日で表示を終了し、採用では延長しません。正式な学習履歴の保持期間とは別です。

## 開発担当者向けの適用

`receiver.patch` はCANVASLMASカスタム層の基準HEAD `6740d7b5ca27a7365b863b155fb948f9c9867fcb` への累積差分50ファイルです。教材リポジトリへ直接適用したり、以前の累積パッチへ重ねて適用したりしないでください。

1. 基準HEADの隔離コピーと [manifest.json](manifest.json) の適用前ハッシュを確認。
2. `git apply --check --whitespace=error-all receiver.patch` の後、隔離コピーへ適用。
3. 隔離DBで `0017_canvas_quiz_review` と `0018_canvas_quiz_decisions` を含むマイグレーションを適用。
4. `TRAINING_DB_TEST=1` で単体テスト、`node node_modules/@playwright/test/cli.js test --config playwright.quiz-review.config.ts` で関連E2Eを実行。後者はloopbackのテストDB（55442、aischool_test）限定。
5. 現行サーバーソースとの統合・レビュー・本番反映は別途実施。

|設定|役割|
|---|---|
|CANVAS_REVIEW_INSTANCE|保存元の固定識別子|
|CANVAS_REVIEW_ORIGIN|CanvasのHTTPSオリジン。直接取得ではCANVAS_BASE_URLとの一致が必要|
|QUIZ_REVIEW_PUBLICATION_ENABLED|`true` の場合だけ採用と本人表示を有効化。初期状態は無効|
|QUIZ_REVIEW_RETENTION_ENABLED|`true` と `--apply` の組み合わせで期限切れコピーの削除。初期状態は件数確認|

既存のCanvas API・LTI設定を利用します。資格情報・生CSV・実在受講者の記録は同梱していません。
