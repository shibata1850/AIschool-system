# 講師画面から分析CSVの作成を依頼する

2026-09-19。**受信側の開発用パッチ。本番の受講者・講師画面への配備は未実施。**

## 操作

1. 「小テスト結果の確認」で対象の小テストを選ぶ。
2. 「CSVの作成を依頼」を押す。全受験回を含む受講者分析CSVをCanvasへ依頼する。
3. 順番待ち・作成中の場合は「準備状況を確認」を押す。ページを再読み込みした場合も、小テストを選び直して状況を確認できる。
4. 準備完了後に「分析CSVを取得して保存」を押す。取得・設問検査・本人対応の検証を経て、講師の確認待ち一覧へ保存する。
5. 最新の受験や再採点が反映されているかはCanvasの答案画面で確認する。確認待ち保存だけでは受講者に表示しない。

**準備完了は、最新性の確認完了ではない。** Canvasは既存レポートを再利用することがある。ファイル更新日時と状況確認日時を分けて表示し、`freshness: unconfirmed` を維持する。強制再生成やレポート削除は行わない。

## 状態と再試行

| 状態 | 表示・操作 |
|---|---|
| 未作成 | 作成依頼を案内 |
| 順番待ち／作成中 | 状況確認を案内。重複の作成依頼・取得保存を止める |
| 準備完了 | CSV取得と保存が可能。以前のCSVの再利用・最新性未確認を明示 |
| 作成失敗 | Canvasの分析画面とサーバー処理状況の確認を案内 |
| 情報不足・不明な生成状態 | 再確認を案内。新たな作成依頼を送らない |
| 作成依頼後の通信失敗など | 「結果を確認できません」と表示。自動再送せず、状況確認ができるまで画面の依頼・保存操作を止める |

- POSTがタイムアウトしても、Canvasが既に受け付けた可能性がある。そのため自動再試行しない。
- Canvasが生成中を示すHTTP409を返した場合は、状態を読み直す。POSTは繰り返さない。
- 状況確認は講師のクリックによるGETのみ。常時ポーリングはしない。

## 実装

- `POST /api/teacher/quiz-review/prepare`：作成依頼。受け取るのは小テスト番号だけ。送信元、LTI担当権限、Canvas上の現在の教員在籍、対象コース、登録済み小テストを検査する。
- `GET /api/teacher/quiz-review/prepare?quizId=…`：同じ権限検査で状態確認。重複パラメータ、余分なURLパラメータ、不正番号を拒否する。
- 作成前に既存の生成状況を読む。順番待ち・作成中・状態不明ならPOSTを送らない。
- Canvasへの書込みは、固定した対象の `/api/v1/courses/{courseId}/quizzes/{quizId}/reports` への作成依頼のみ。`student_analysis`／`includes_all_versions=true` をサーバー側で固定する。答案・成績・教材・削除APIは呼ばない。
- 認証は設定済み同一オリジンのみに送る。進捗URLは同じオリジンの進捗APIだけを許可し、リダイレクトを拒否する。通信は各20秒、メタ情報は実読取256KBまで。
- ブラウザーには固定の状態・説明・日時だけを返す。進捗の生メッセージ、回答、氏名、ファイルURL、署名情報、API認証値は返さない。
- 外部への依頼に先立って、操作者・対象コース／小テスト・要求IDの監査記録を保存する。結果も追記する。途中で記録が止まった要求は結果未確定として残り、完了したと見なさない。
- 取得後の保存経路・30日の表示期間・重複防止・再採点の別候補保持は [CSV取得の仕様](CSV_ACQUISITION.md) を利用する。作成依頼だけでは得点候補を保存しない。

## 検証

- 新規24単体テスト：一度だけのPOST、既存CSV再利用、5状態のGET確認、生成中の再送防止、409、POST後の通信失敗／429／500／別小テスト応答、異なるオリジン、不正な進捗／ファイルURL、匿名・サイズ・重複・不正JSON、情報不足を検査。
- 架空Canvasと隔離DBのE2E：作成依頼→順番待ち→準備完了→取得保存、未確定からの状況確認、重複依頼防止、権限拒否、入力境界、監査記録を確認。3画面条件で実施し、最新結果は `verification.json` に記録する。
- 稼働Canvasでは、許可済み架空デモの小テスト1件へ作成依頼を1回だけ送信し、受理・準備完了を確認。その後に取得したCSVの12問が、以前の検査済み変換結果と一致した。新規生成か再利用かの断定はしていない。
- 実環境で行った書込みは分析CSVの作成依頼1回のみ。成績・答案・教材・本番アプリコードの変更、直接のDBアクセス、レポート削除は行っていない。原本CSV・個別ID・個別得点・認証情報はパッケージと検証記録に含めていない。
