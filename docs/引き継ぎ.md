## 2. なぜ「1か所で」なのか

これまでは、コードを書く側（Claude Code on the web）がサーバーに届かず、
サーバー作業だけをCoworkへ**プロンプトを転記して**頼んでいた。転記が多いのはそのため。

**開発機（HP Z4 G5）で Claude Code か Cowork を動かせば、コード・テスト・サーバー・
Canvas管理画面のすべてに1つのエージェントが届く**ので、転記は無くなる。
必要なのは開発機に次が揃っていること:

- Git・Node.js・npm（`npm ci` が通ること）
- PostgreSQL（単体テストとE2Eが使う。`infra/custom-layer/README.md` のロール設計と同じ2ロール）
- Playwright のブラウザ（`npx playwright install chromium`）
- 本番サーバーへの SSH 鍵（Coworkが既に使っているもの）
- `.env` と `.env.test`（`.env.example` から作る。**コミットしない**）

注意: 開発機は講師機・コンテンツ制作機と兼用（CLAUDE.md 6章）。開発用ユーザーを分け、
授業時間帯のビルドを避ける。

## 3. 作業の作法（これまでのプロンプトで毎回付けていた約束。CLAUDE.md 14章に正式化）

1. **サーバー上で `.env` を丸ごと表示しない。トークン・鍵の値をチャットに書かない**
2. **破壊的操作（コンテナ・ボリューム削除、DBのDROP、force push、Canvasのユーザー・キー削除）は
   実行せず、必要だと思ったら止めて報告する**
3. 反映の手順は固定: `git pull` → HEAD確認 → （あれば）バックアップ日付確認 → マイグレーション →
   ビルド・再起動 → `docker compose ps` とトップページのHTTPステータス → 画面で動作確認 → 報告
4. Canvasの管理画面は「編集」まで。削除・再インストールはしない
5. 報告は**画面に出た文言をそのまま**書く（「正常でした」ではなく何が表示されたか）
6. 秘密情報が要るコマンドは、環境変数を参照させて値を出力しない
   （例: `docker compose exec -T app node -e '... process.env.CANVAS_API_TOKEN ...'`）

## 4. コード側の検証パイプライン（コミット前に必ず）

```
npx tsc --noEmit
npm run test:unit
npm run build
npx playwright test          # 全件。Chromium同梱環境では PLAYWRIGHT_CHROMIUM_PATH=<path>
git checkout -- next-env.d.ts   # next dev が書き換えるため戻す
```

- 機能コードとE2Eは**同じコミット**（CLAUDE.md 7章）
- バグ修正は**再現E2Eを先に書いてFAILを確認**してから直す（`e2e/regression/` に日付付き）
- コミットは Conventional Commits・日本語本文

## 5. ハマりどころ（実際に踏んだもの）

| 事象 | 対処 |
|---|---|
| Drizzle のマイグレーション `.sql` を書いても適用されない | `drizzle/migrations/meta/_journal.json` にエントリを足す必要がある |
| `"use client"` の部品がDBを引くモジュールを import して15件落ちる | 定数は `src/lib/f2/constants.ts` のようにDB非依存のファイルへ分ける |
| 表示制約テストで「32pxのボタン」が出る | Next.js の開発ツール（`NEXTJS-PORTAL` の shadow DOM）。テストで除外済み |
| `getByRole("alert")` が2件に当たる | Next.js のルート通知も alert。本文で引く |
| E2Eが `/api/dev/reset` 404 | Playwright が dev サーバーを自分で立てる前提。手で `npm run start` していると起きる |
| LTIの `sub` と Canvas REST の数値ID が別物 | 名簿は `students`（LTI起動で記録）が正。REST用の数値IDは `canvas_user_id` に別で持つ（B15） |
| Canvasの開発者キーを直してもアプリに効かない | Canvasの裏の処理（jobs）が動いていなかった（B21）。今は起動済み |
| Canvasメッセージが受信箱に無い | 送信者＝宛先（管理者＝唯一の教員）だったため。講師アカウントを分ける（B22） |
| 本番サーバー再起動後にCanvasが上がらない | compose に restart 設定が無い。systemd ユニットで対処（B23） |
| モックの障害模擬 | 質問に `【障害模擬】` を含めると失敗になる（本番のClaudeでは発動しない） |
