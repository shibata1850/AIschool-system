## 2. 最重要 — 二重計上リスク

先方文書 第2章が「本書の最重要事項」として、機能が重なると
**補助金の実績報告で二重計上と判断される**と明記している。

これは `CLAUDE.md` 10章（ノーティ納品分とSOFTDOING参照実装の計上を混ぜない）と
**別種のリスク**である。10章は「同一補助金内で、誰の成果物かを取り違えない」話。
本件は「**別々の補助金にまたがって、同じ機能を二度計上しない**」話。両方守る。

実装禁止範囲は `CLAUDE.md` 13.1。要望が来ても要望リストへ回さず差し戻す。

### 3.2 影響あり（未着手・要判断 → 未決事項 #13）

先方 E7「クラウドキャンパス連携」は、**本リポジトリ側の対応がないと成立しない**。
先方の受け入れ基準 A-3（SSO）と B-7（到達度反映）が本リポジトリに依存する。

```
  [クラウドキャンパス]                    [eラーニングシステム]
   Canvas LMS + カスタム層                  独立Webアプリ
   ・受講生マスタ（正）        --SSO-->     ・同じIDでログイン
   ・コース／単元マスタ（正）  --API-->     ・単元を参照
   ・到達度ダッシュボード      <--API--     ・自宅学習の到達度を送る
```

| # | 必要な対応 | 本リポジトリの作業量 | 論点 |
|---|---|---|---|
| E7-a | eラーニングをCanvasの開発者キーに追加しSSOさせる | **コード変更なし**（Canvas設定のみ） | 誰が設定するか。手動対応リストへ追加が要る |
| E7-b | 単元マスタの参照手段を提供 | 小〜中 | Canvas REST APIを直接叩かせるか、カスタム層にAPIを作るか。**トークンを相手に渡す是非**（Canvasの管理者トークンは権限が広すぎる） |
| E7-c | **到達度スコアの受信APIを新規実装**しF4に表示 | **中**（新規エンドポイント＋認証＋監査ログ＋E2E） | 認証方式、スコアの単位（先方は「単元別0〜100」、本リポジトリは週次到達度）、**対面の到達度と自宅学習の到達度をどう合成して見せるか** |
| E7-d | 受講生削除の伝播 | 小 | 本リポジトリは `purgeStudentData` を持つ。通知手段（Webhook/ポーリング）が未定 |

**E7-c の合成方針が最大の論点。** 本リポジトリの到達度は
「講師スコア0.6＋AI採点0.2＋出席0.2」の週次値。先方は「視聴完了率・小テスト正答率・
誤答分布・経過日数」からの単元別値。**別物を1つのダッシュボードに並べるのか、
合算するのか**を決めないと画面が作れない。合算するなら重み付けの決定権者も要る。

## 4. 見落としやすい副作用

### 4.1 同一サーバーの共有（先方 3.1）

先方は「発注者が契約する**さくらのクラウド**。クラウドキャンパスとは**別のインスタンス
または別コンテナ**として分離して稼働」としている。現在 133.125.225.64 では
Canvas本体＋カスタム層＋PostgreSQL が動いている。ここに動画配信を伴う
eラーニングが同居すると、**CPU・メモリ・帯域・ディスクを奪い合う**。

- 望ましいのは**別インスタンス**。同一インスタンスに同居させるなら、
  リソース上限（`deploy.resources`）とディスク容量の事前見積りが要る
- サブドメインも別（例: `learn.ngas.jp`）。本リポジトリの独自ドメイン移行
  （手動対応リスト B3）と**まとめて決めた方がよい**

### 4.2 ノーティのリソース競合（スケジュール）

先方 第10章は「着手から検収まで**約5週間しかない**」「E4が遅れると納期全体が崩れる」
と自認しており、検収は **9月30日**。本リポジトリのノーティ納品分の受け入れテストは
**9月中下旬**で、完全に重なる。

**本リポジトリはSOFTDOINGの参照実装（バックアップ）であり、この競合そのものが
`CLAUDE.md` 10章が想定したリスク（過去の委託案件での要件未達）の再来になり得る。**
本リポジトリの完成度を上げておく判断は、この文脈でも正しい。

### 4.3 先方文書に残る前提のズレ（本リポジトリへ持ち込まない）

先方 1.3 の対象利用者に「中学生・高校生・大学生」、3.2 に「未成年が含まれる」とある。
これは eラーニング側の対象。本リポジトリの対象は**企業・行政の社員（成人）**で確定済み
（`CLAUDE.md` 9章・パンフレットv2）。SSO で同じ受講生マスタを共有するため、
**マスタ側（本リポジトリ）に未成年が入ってくるのか**は確認が要る（未決事項 #13）。
入るなら 9章の個人情報の扱いを見直す必要がある。
