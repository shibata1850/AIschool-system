## 3. 隘路が示した見解（要点。後から「なぜそう決めたか」を追うため）

### 3.1 AI講師の位置づけ（9/2、確認事項A-2への見解）
- 座学を事前収録にするのは**可用性の面で正しい**（推論を使わないのでAI停止でも座学は止まらず、KPI#1と両立）
- 実習中の「BASE44の操作」相手としては**不要**（BASE44自身のAIより正確にならない・仕様変更への追随コスト・スコープ外）
- それでも**AI講師は残す**: 先方文書2.2が「AI講師との対話＝クラウドキャンパス側」と外から認めており、消すと境界の主張が弱まる。BASE44にできない3つ（本校のカリキュラムに答える／「何を作るべきか」の言語化／機密の安全な取り扱い＝マスキング・監査・保持期間が効く窓口）
- 線引き: 座学＝事前収録／BASE44操作＝使わない／カリキュラムと「何を作るか」＝使う／機密を含む相談＝使う

### 3.2 ハルシネーション（9/3）
- 短縮は誤りの「率」ではなく「コスト」を上げる（含みが落ちて断定調になる）→「不確かなら断定しない」を同梱する
- 本当のリスクは一般技術知識ではなく **本校のカリキュラム**と**BASE44の具体操作**（モデルが知らない・古い）
- RAG（事例のナレッジ化）は万能ではない: 範囲外で黙る規律が先／事例には顧客名が入るので匿名化必須／教材未作成のため今は着手不能
- 測り方: F2①の10問をハルシネーション確認と兼ねる（一般4・カリキュラム3・BASE44 3）

### 3.3 「分からないことがないAI」は作れない（9/3）
- 原理的に知り得ない3つ: BASE44の最新仕様・受講生の自社業務・まだ書かれていない教材
- 講師にIT知識が無い体制では、**AIが間違えても誰も止められない**。目指すべきは「分からないときに確実に分からないと言い、次の行き先を示すAI」
- 役割分担: BASE44操作→BASE44自身／カリキュラム→AI講師（教材待ち）／業務課題の言語化→事前ヒアリング＋ディスカス／**それでも解決しないもの→行き先が未定**（この問いが 9/7 のローカルAIの話につながった）
- 要件定義書2.2「講師: AIツール研修済み」と食い違うことを指摘

### 3.4 属人性と会話ログ（9/3）
- 教材は2種類: 受講生向け教材（AIのRAGにも効く）と**講師向け手順書（属人性に直接効くのはこちら。見積F6 ¥432,000の中身がまだ無い）**
- 机上のFAQは当たらない。**第1期に隘路が聞かれたことを記録し、教材・手順書へ還元する**のが属人性解消の唯一の道 → そのために会話ログ保存が要る（当時は未実装で、A-3で保持期間だけ先に決めていた行き違いを認めた）
- 誤りは2種類: **動かして分かる誤り**（受講生が気づく）と**動いてしまう誤り**（データ設計・個人情報・権限・業務ロジック — 誰も気づかず本番稼働する）。守るべきは後者 → **断定禁止領域**（「大丈夫です」と答えさせない）
- 5層: BASE44へ誘導／不確かなら答えない／断定禁止領域／注記で誤りやすい所を名指し／会話ログで事後に拾う。＋運用でSTEP09レビュー会に設計・個人情報の観点を組み込む。**残余リスクはゼロにならない**と明言

### 3.5 「一言送る」（9/4）
- 当初「対面で文字を打つのは遅い」と否定していたが、**「この内容をプロンプトに入れてみてください」は口頭では渡せない**の一点で撤回
- Canvas標準Inboxは別画面・非同期で授業中には重い → S6のタイルから講師→受講生の一方向テキスト（履歴保存・コピー可）に絞る。見積6項目に無い新規機能だがF4の拡張として説明でき13.2の範囲内

### 3.6 教材の形式・未決#14・講師用ローカルAI（9/7）
- 2つは同じ問題の表裏（AIが「分からない」ときと「止まった」とき）。**検収に必須なのは#14だけ**
- 教材はAIに読ませるなら**文字として取り出せる形**（Markdown か Canvasページ）。PowerPoint・Canva・画像PDFを「正」にしない。1本の教材が4役（受講生が読む／停止時の誘導先／クラウドAIの知識／講師用ローカルAIの知識）
- 未決#14: A-1a（教材リンク）＋A-1c（講師に聞く）の併用。A-1b（eL）は後からリンクを足すだけ
- 「講師も分からない」は3種類: ①教材に書いてある（AIで解ける）②BASE44操作（BASE44へ）③判断が要る（誰も断定すべきでない→柴田さまへの連絡経路。**AIでは消せない**）
- 講師用ローカルAIの3条件: **講師専用・出典必須（教材のどのファイルのどの見出しか）・講師機で完結**（クラウドから教室のGPUは呼ばない）。時期は開校後

### 3.7 位置関係と補助金（9/2）
- クラウドキャンパス: SOFTDOING→ノーティ→隘路（再委託）。本リポジトリ＝ノーティの納品物。「事務局確認不要」は筋が通る。ただし**再委託条項**の確認（未決#15）
- eラーニング: ノーティへ外注費を払う一方で実装がSOFTDOINGの従業員（予定）だと**証憑と実態が食い違う**（未決#16。選択肢4つを記載）
- 機能境界13.1は「誰が管理するか」ではなく「どの補助金に計上するか」で決まるので維持
