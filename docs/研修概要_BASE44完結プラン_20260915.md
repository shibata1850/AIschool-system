# NGAS BtoB研修概要：BASE44完結プランと発展プラン

- 作成日：2026-09-15
- 状態：ユーザーと合意した授業構成案。教材・設問・修了基準の詳細は未確定。
- 対象：企業・行政の社会人。学生向けコースとは分ける。
- 本文の保存は仕様整理であり、アプリ実装・Canvas設定・本番反映を指示するものではない。

## 1. 研修の考え方

ゴールは、業務で使う動くシステムを作り、運用につなげること。
知識の完全定着や設計書の提出を開発開始の条件にしない。
実際に作りながら理解を深め、安全上重要な事項は繰り返し確認する。

- 採用する開発プランで実際に使うツールだけを教える。
- Notion、Wix、Canvaなど、今回使わないサービスの操作講座は入れない。
- 提出課題・宿題・採点用の設計書をBtoBの必須要件にしない。
- 作る範囲や未決事項を忘れないための短いメモは残す。
- 「画面が動く」と「安全に本番運用できる」を分け、公開前は講師が確認を支援する。
- 自社業務を題材にしても、練習・検証では機密情報や個人情報を含まないデータを使う。

## 2. 2つのプラン

| 項目 | BASE44完結プラン | 発展プラン |
| --- | --- | --- |
| 開発の中心 | BASE44 | CodexまたはClaude Code |
| 公開先 | BASE44内で完結 | さくらのクラウド |
| 研修の範囲 | 作成・修正・検証・公開準備・運用 | 個別要件に応じた開発と検証 |
| 研修後 | 準備状況に応じて本番投入を伴走 | 本番移行監修と継続支援を別立てで組む |
| 時間 | 4時間×10日、40時間 | 40時間に収まるとは決めず、追加工程を見積もる |

発展プランでは、国内サーバーが必要な理由とシステム規模を別々に確認する。
大規模システム全体の完成を1コースで約束せず、対象業務を絞って検証環境で動かし、
修了後に段階的に拡張する。

国内サーバーへの設置と、開発時の情報の送信先は別の論点。
AI開発ツールに渡すコード・データを含めて利用条件を確認する。

### 監修と保守の区別

- 監修：受講者による設計・変更内容を確認し、改善や公開判断を支援する。
- 保守：契約範囲に応じて更新、監視、バックアップ確認、障害対応などを実施する。
- 対応範囲、担当、時間、責任分担、費用は別途定義する。即時復旧や常時対応を暗黙に約束しない。

## 3. BASE44完結プランの到達目標

- AIに作りたいものを伝え、画面や動作を見ながら修正を依頼できる。
- 機密情報・個人情報・認証情報を不用意に渡さず、迷ったら相談できる。
- 自社の対象業務を、練習用データで開始から完了まで試せる。
- 入力ミスや権限の違いを含めて確認できる。
- 研修後の担当、残作業、公開判断、相談先が分かる。

## 4. 10日間の授業構成

パンフレットの9STEPに対応し、STEP05を2日間とする。
各日240分。講義・実演・作業190分、休憩20分、小テスト・解説30分を基本とする。

### 1日目：AI基礎・安全利用（STEP01）

到達点：安全に触り始め、作れる感覚をつかむ。

| 時間 | 内容 |
| --- | --- |
| 0〜20分 | BASE44の業務システム完成例を見る |
| 20〜50分 | AIにできること、任せきれないこと |
| 50〜90分 | 入力情報、公開範囲、認証情報、人による確認 |
| 90〜100分 | 休憩 |
| 100〜145分 | 作成・修正の伝え方を実演 |
| 145〜180分 | 最初の画面を作り、1か所修正する操作体験 |
| 180〜190分 | 休憩 |
| 190〜210分 | 振り返り・質問 |
| 210〜240分 | Canvas小テスト・解説 |

専門用語やAIの内部構造の暗記は求めない。操作体験は提出・採点しない。
小テストは情報の入力、出力確認、修正依頼、一般利用者の権限、公開前の判断を扱う。

### 2日目：作る業務を決める（STEP02）

到達点：最初に何を作るか、本人と講師の認識が揃う。

- 講義・実演40分：業務システム例と、一つの手間を減らす考え方。
- 作業120分：現在の作業と困りごとを話し、講師と最初の範囲を絞る。
- 共有30分：誰が使うか、何を楽にするか、最初にできればよいことを確認。
- 小テスト：開発範囲の選び方、実データ使用前の確認。
- 提出物は不要。次回迷わない程度の短いメモを残す。

### 3日目：使う流れを具体化する（STEP03）

到達点：利用者が最初から最後まで何をするか説明できる。

- 講義・実演40分：登録、確認、対応、完了などの流れを画面例で説明。
- 作業120分：入力・閲覧・承認する人と必要な情報を確認。必要ならBASE44で画面のたたき台を作る。
- 確認30分：講師と利用場面を通す。未決事項は保留と分かるよう残す。
- 小テスト：閲覧と編集の違い、入力漏れ、差戻し。
- 設計書や権限表の提出は不要。ただし権限の判断を曖昧なまま公開しない。

### 4日目：BASE44の基本操作（STEP04）

到達点：作成・修正を依頼し、自分で結果を確認できる。

- 講義・実演60分：作成依頼、画面確認、修正依頼、データと利用者権限の基本。
- 操作100分：主要画面を作り、項目・表示・動作を変更する。
- 振り返り30分：伝わった依頼と伝わらなかった依頼を比較。
- 小テスト：修正の伝え方、変更後の確認、相談。
- BASE44の全機能は網羅せず、今回使う操作に限定する。

### 5日目：開発①・中心となる操作を作る（STEP05前半）

到達点：最も重要な操作が練習用データで一度動く。

- 実演20分：依頼を小さく分け、一つずつ確認する。
- 開発140分：登録・一覧・詳細など必要最小限の操作を作る。
- 確認30分：講師に動かして見せ、次に直す箇所を決める。
- 小テスト：保存の確認、エラー発生時の伝え方。
- 見た目や追加機能より中心の操作を優先する。

### 6日目：開発②・業務をつなげる（STEP05後半）

到達点：対象業務を開始から完了まで試せる。

- 実演20分：状態変更や複数画面をまたぐ操作。
- 開発140分：必要に応じて検索・承認・状態変更などを追加する。
- 確認30分：利用者の立場で通し、迷う箇所を修正する。
- 小テスト：追加機能の優先順位、変更の影響。
- 研修内の範囲と後日追加する範囲を分ける。

### 7日目：不具合と想定外の操作への対応（STEP06）

到達点：問題を再現し、修正後に確かめられる。

- 講義・実演40分：空欄、重複、誤入力、やり直し、権限違い。
- 作業120分：自分のシステムで試し、問題を具体的に伝えて修正する。
- 確認30分：同じ操作を再実行し、他の動作への影響も確認する。
- 小テスト：起きたことと期待したことの区別、修正完了の判断。
- そのシステムに関係する確認項目を選ぶ。

### 8日目：利用者として通し確認する（STEP07）

到達点：使える範囲と、公開前に直す箇所が分かる。

- 実演30分：利用者の権限で一連の業務を確認する。
- 作業130分：通常の流れと代表的な例外を確認。可能なら講師が利用者役を担当。
- 整理30分：公開前に必ず直す、当面の運用で対応、後日改善に分ける。
- 小テスト：管理者だけの確認が不十分な理由、公開を見送る判断。
- 記録は簡単なチェック一覧とし、採点用の提出課題にはしない。

### 9日目：本番移行を準備する（STEP08）

到達点：公開可否を判断する準備が揃う。

- 講義・実演50分：公開範囲、利用者、データ投入、停止・復旧方針。
- 作業110分：練習用データで投入手順を試し、設定・操作手順を確認。講師が重要事項を点検。
- 確認30分：残る問題と担当を決める。
- 小テスト：公開前の確認、実データの扱い、問題が残る場合の判断。
- 当日の本番公開は必須にしない。準備状況を確認し、修了後の伴走につなげる。

### 10日目：研修後の運用を決める（STEP09）

到達点：担当、費用、相談先が明確になる。

- 講義・実演40分：利用費、管理担当、変更時の確認、障害・問い合わせ対応。
- 作業100分：システムを説明・実演し、操作と運用上の注意を短く整理する。
- 個別確認50分：残作業、公開予定、支援、追加開発を確認する。
- 最後30分：修了時の習熟度テストと解説。基準・再確認方法は別途定義。
- 成果物の完成度だけで修了を決めず、修了判定と本番運用の可否を分ける。

## 5. 小テストと修了判定

- 各日の最後30分を小テストと解説に充てる。回答20分、解説10分は目安。
- Canvasの既存機能を活用する方針。機能と設定は実機確認してから決定する。
- 日々の問題は暗記より判断を重視し、理解状況を講師が把握するために使う。
- 安全上重要な誤答は補足する。全問正解まで一律に開発を止める方式にはしない。
- パンフレットは出席時間が総訓練時間の8割以上、かつ習熟度テストによる修了判定を記載している。
- 合格点、問題数、再試験、欠席時の扱い、休憩と訓練時間の数え方は未確定。
- 上記は研修案であり、助成金等の制度適合を確認したものではない。
- 対面授業の確認テストと、eラーニングの章末テストを区別する。
  既存CLAUDE.md第13章の機能境界を、この文書だけで変更しない。

## 7. システムの役割と今後の作業

- Canvas／カスタム層：コース、出席、当日の案内、講師相談、対面研修の記録。
- eラーニング：教材閲覧・復習を中心に検討。理解度スコアや弱点復習を一律の進行条件にしない。
- 課題提出・採点の既存機能は、学生向け等で活用できるため削除を決めたものではない。
- BtoBと学生向けはコースを分ける。ホーム・メニューの切替は今後の仕様整理対象。
