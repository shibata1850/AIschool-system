# BASE44完結プラン：教材章立て・小テスト設計案

作成日：2026-09-15
状態：研修概要に基づく編集案。問題数・配点・合格基準は未承認。
関連：[研修概要](研修概要_BASE44完結プラン_20260915.md)

## 1. 編集の原則

- 自社業務のシステムをBASE44で作る研修。Notion等の操作は教えない。
- 各章は「必要になる場面→短い説明→実演→本人が試す」の順にする。
- 専門用語、AIモデル比較、使わないサービスの説明で時間を埋めない。
- 操作を覚えきれなくても、参照・質問しながら進められる。
- 安全性、権限、実データ、本番公開の判断は省略しない。
- 内容が異なる自社業務を、同じ成果物・同じ画面構成に揃えない。
- 発展プラン用のGit、Codex、Claude Code、サーバー構築は混ぜない。

## 2. 教材の構成

各日、受講者向け本文と講師用ノートを分ける。
本文には到達目標、章ごとの説明、操作例、振り返りを収録する。
講師用ノートには実演準備、つまずき例、巡回時の確認、解答解説を収録する。
解答・解説の原本をそのまま受講者教材や未回答のテストへ添付しない。

4時間枠は講義・実演・作業190分、休憩20分、確認テスト・解説30分。
テスト前に未習事項を追加して出題しない。

## 4. 日々の小テストの設計案

- 各日8問を初稿の目安とする。正式な問題数ではなく、試行後に所要時間で調整する。
- 原則は短い場面設定に対する単一選択式。最も適切な行動を1つ選ぶ。
- 複数選択が必要な場合は選択数を明記し、部分点の扱いを先に決める。
- 安全に関わる問題を2問程度含める。全員が同じ題材を開発している前提にしない。
- 数値スコアは理解状況の把握用。合格点や自動進行制限はまだ設定しない。
- 自由記述や成果物の採点を前提にせず、講師の採点負担を増やさない。
- 回答20分、解説10分を目安にする。短い設問で読む負担を抑える。

### 設問原稿の項目

| 項目 | 内容 |
| --- | --- |
| 設問ID | B44-D01-Q01のように日と問題を識別 |
| 学習目標 | 何を判断できるか |
| 問題文 | 必要条件を明示した短い場面 |
| 選択肢 | 明確な違いのある3〜4択 |
| 正答 | なぜ適切なのか説明できるもの |
| 解説 | 正答の理由、誤答の問題、実務での行動 |
| 安全項目 | 情報・権限・公開等の重要問題か |
| 講師補足 | 誤答が多い場合の短い実演や説明 |
| 確認状況 | 教材との対応・表現・現行仕様の確認 |

### 設問を作る際のチェック

- 文面にない社内ルールや契約条件を推測させない。
- 絶対表現を使ったひっかけや、常に同じ位置の正答を避ける。
- 「AIが生成したから安全」「公開URLを知られなければ安全」などの誤解を説明する。
- 社内の実情報、実際のパスワード・トークンを出題に使わない。
- UIのボタン名や料金を暗記させない。未検証の機能を正答の前提にしない。

## 5. 修了時テストとの区別

10日目は総合確認として、複数日の内容をまたぐ場面問題を用意する。
問題数、合格点、再確認方法、採点結果の扱いは確定前に協議する。
日々のテストの点数を自動的に修了点へ合算することは決めていない。
知識の定着が十分でない場合の補足と、本番公開を止める判断は別々に扱う。

4. 修了基準と公開前点検を確定する。
