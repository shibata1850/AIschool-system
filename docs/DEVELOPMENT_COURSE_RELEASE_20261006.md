# システム開発コース実装・反映記録

## 範囲

既存の演習型・BtoB研修型を維持し、明示的な「システム開発コース」を追加する。
教材そのものの10日分の再編は別工程。現時点のリンクを新しい教材が完成したものとして扱わない。

- 本人用：教材の3分類、授業一覧、開発システム情報、編集用/確認用URL、授業回別の作業状態、相談希望・進捗メモ。
- 講師用：受講者一覧、相談対応、授業回別出席・欠席・遅刻・早退、記録の訂正。
- 作業状態・出席・小テストは相互に自動換算しない。小テストは開発コースのホームに表示しない。
- 別受講生の開発情報は取得・変更不可。講師の別コース閲覧は従来方針を維持、変更は起動したコースのみ。
- 変更は監査ログと同じトランザクション。revisionの比較により上書きを防ぐ。
- 退会時の名簿削除に伴い新規3テーブルの個人記録を外部キーで削除。監査ログは従来の保持方針。

## URLと運用

外部リンクはサーバーで取得しない。HTTPSのみ、ユーザー名・パスワード・クエリ・フラグメントを拒否する。
パスに秘密情報を含むURLも登録しない。登録はリンク先へのアクセス権付与ではなく、BASE44側の権限管理は別途必要。
講師一覧の受講者はCanvasのコースからLTI起動した名簿が基準。まだ起動していない人を欠席と自動判定しない。
正式な受講時間の算定・修了条件は未確定であり、今回の出席記録から自動認定しない。

## 本番E2Eシナリオ

架空のデモ生徒のみを使用。既存の教材URLと授業名は変更しない。

1. 講師でシステム開発コースを選び、授業回を設定・保存する。
2. デモ生徒でCanvasから起動し、教材と開発情報の入口を確認する。小テスト・課題の必須ゲートがないことを確認。
3. システム名・困りごと・HTTPSリンクを保存し、再読込で維持されることを確認。
4. 教材確認中＋相談希望、開発中＋相談希望を保存。講師一覧・本人再表示で一致することを確認。
5. 講師が相談を対応済みにし、作業状態が変わらないことを確認。本人の取り下げ・再依頼を確認。
6. 出席・遅刻・早退・欠席・未記録への訂正を架空生徒で確認。履歴を監査件数/存在で確認。
7. 第2回へ切り替え、作業状態は未設定、システム情報は維持されることを確認。終了時は授業未選択へ戻す。
8. 不正URL、古いrevision、受講者による講師画面直接アクセス、別受講者・別コースの取得/変更拒否を確認。
9. 通信失敗で保存済みと表示しないこと、モバイル/デスクトップで見切れないことを確認。
