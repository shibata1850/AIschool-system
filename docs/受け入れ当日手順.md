## 1. 実施順（この順に流す）

**順番には理由がある。** ①が通らないと他は全部無意味なので必ず最初に置く。

### ① LTI起動と権限の実機確認（最優先・所要30分）

これが通らなければ授業が成立しない。**16台すべてで確認する**。

1. 各NUCのブラウザでCanvasにログイン（**16台それぞれ別の受講生アカウント**）
2. コースナビの「AI講師・演習」を開く
3. カスタム層の画面が出て、**「今日やること」に自分の課題が出る**こと
4. 講師機で講師アカウントとして起動し、「講師用メニュー」が出ること
5. 管理者アカウントで「管理者メニュー（監査ログ・Canvas連携状況）」が出ること

**確認の勘所**: 16台が**同じ `student-demo` になっていないこと**。全台で同じ課題状態が
見えていたら、LTIのユーザー識別ができておらず、デモIDを共有している。

> ここで失敗した場合、`DEMO_RICH_SEED` が `1` になっていないか確認する
> （このとき全員がデモ生徒として表示される仕様 — `src/lib/auth.ts`）。

6. **16台の起動が済んだら、講師機で S9「デバイス割当」を開き、座席を割り当てる**
   （各行の「受講生の割当」で受講生を選び「保存」）。

   **なぜここでやるか**: 名簿はLTIで一度起動した人から作られる。起動前は
   誰も選択肢に出ない。逆に、割り当てるまで S6 モニタリング・S8 レポートの
   **座席番号は 0**（＝座席なし）で、4×4の座席順に並ばない。
   初期データの架空の割当が残っている席は「名簿にない割当（…）」と黄色で出るので、
   実受講生に付け替えるか「空席」を選ぶ。

   同じ受講生を別の席に選び直すと、前の席は自動で空席に戻る（席を移した扱い）。
   **これは同じ人（同じID）のときだけ**なので、初期データの割当（`student-demo` など）は
   表示名がたまたま似ていても別扱いで残る。16席すべてに実受講生を割り当てれば
   上書きされて消えるため、個別に消す作業は不要。

### ② 16台同時の負荷試験（所要60分・KPI#1）

**合格基準**: システム起因の中断0件／画面遷移3秒以内・提出5秒以内（90%ile）

1. まず**サーバー側の同時処理能力**を再確認する（搬入前と同じコマンド）:
   ```
   npm run test:load -- --base-url https://<本番URL> --clients 16
   ```
2. 次に**実機16台での通し**。90分1コマ分のシナリオを人が操作する:
   - 全員でログイン（①の状態から続行）
   - 教材を開く → プロンプトを書く → AI講師に1回質問する → 提出する
   - 講師機でS6モニタリングを開き、**16タイルが全部埋まる**ことを確認
   - 講師が2〜3名を採点し、S7で「完了にする」→ Canvas成績表に載ることを確認

**中断としてカウントするもの**: 画面が真っ白／エラー画面／操作しても反応しない／
30秒以上戻らない。**カウントしないもの**: 受講生の操作ミス、Wi-Fiの一時的な切断で
再読込すれば戻るもの（ただし回数は記録する）。

**校内LAN越しの体感**もここで見る（Aruba AP-655・10GbE）。数値はサーバー側の
負荷試験で取れているので、ここで見るのは**体感の引っかかり**。

## 3. 講師トレーニング（F6①②）

**判定条件**（要件定義書 9.2 F6）:
- ① 講師が**手順書のみで**通常1コマを自力運営できる
- ② 障害時手順書に従い、クラウド障害を模擬したときに**授業続行の判断が5分以内**にできる

### ①の進め方（60分）

**開発者は口を出さない。** 講師が `docs/デモ手順.md` だけを見て操作する。
詰まった箇所を記録し、その場で教えるのではなく**手順書を直す**。

やってもらうこと:

1. 授業開始前: Canvasにログイン、コースを開く、受講生が揃っているか名簿で確認
2. 授業中: S6モニタリングを開き、停滞している受講生を1人見つけて声をかける
3. ヘルプ要請のタイルをタップして消し込む
4. 授業後: S7で提出物を1件採点し、完了にする
5. S8で週次レポートを開き、停滞アラートを読む

**記録するもの**: 詰まった箇所／手順書のどこを見れば分かったか／所要時間

### ②の進め方（30分）

クラウド障害を模擬する。**本番を落とさない**こと。

模擬の方法（安全な順）:
1. 講師機のブラウザで**機内モード**にする（端末側の切断を模擬）
2. それでも足りなければ、講師機のみhostsでカスタム層のドメインを解決不能にする

講師に判断してもらうこと:
- 授業を**続行するか中断するか**
- 続行する場合、**何に切り替えるか**（配布済み教材・座学）
- 受講生への**アナウンス内容**

**5分を測る。** 判断できなければ、障害時手順書（F6）に不足がある。

> **注意**: AI講師が止まったときに画面へ何を出すかは**未確定**（未決事項#14）。
> そのため現時点では「システムが自動で代替を出す」動作は実装されていない。
> 当日は**講師の運用判断でカバーする**前提で実施し、判断に何秒かかったかを記録する。
