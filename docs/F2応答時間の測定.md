# F2 応答時間の測定

## 区別する時間

| 指標 | 範囲 | 注意 |
| --- | --- | --- |
| サーバーの `[F2] elapsedMs` | answerQuestion周辺の処理 | 認証・会話保存・通信・画面描画を含まない |
| ブラウザの `[F2_UI] method=reply-render-ready-v1` | ask開始から回答のReact反映後、2回目のrequestAnimationFrameまで | ブラウザのperformance.nowで完結。実ピクセル描画・遮蔽・Canvas親フレームの可視性は証明しない |
| `playwright-click-to-visible-upper-bound-v1` | 送信クリックの呼出直前から、新しい回答本文のDOM表示確認まで | 操作・自動待機・ポーリングを含む保守的な値。画面の実ピクセル描画時刻ではない |

各指標を同じ「応答時間」として合算・比較しない。
後者が5秒を超えても、実際の表示が5秒を超えたとは即断できない。
逆にDOMのvisible判定だけでは、画面内に見えていること・他の要素に隠れていないこと・描画完了まで証明できない。

## ブラウザ内の診断値

`TimedReply` は回答がReactに反映された後、2フレームを待ち、ブラウザのコンソールと回答のDOM属性にだけ診断値を記録する。
サーバー送信・DB保存・Cookie・localStorage・新しい環境変数は追加しない。

```text
[F2_UI] method=reply-render-ready-v1 elapsedMs=1234 documentVisible=true inViewport=true
```

- `data-f2-render-ms`: ブラウザ内の経過時間。後から読み取ってもツール待機時間は加算されない。
- `data-f2-document-visible`: 記録時点の文書の可視状態。測定途中に非表示だった履歴は含まない。
- `data-f2-in-viewport`: 記録時点で回答全体がアプリ自身のviewport内に収まるか。Canvas親iframeの位置や他要素による遮蔽は対象外。
- 質問・回答・ユーザーIDを診断ログに含めない。未送信の入力によって過去の値を取り直さない。
- 空回答・ブロック・HTTPエラーは成功のrender診断値を生成しない。試験の全試行数は別に固定し、値のない失敗を母数から外さない。
- ページを離れると記録は消える。ブラウザをバックグラウンドにするとrAFが遅延する可能性があるため、前景での計測と画面確認を組み合わせる。
- この値も厳密な物理描画時刻ではないが、ツール往復を含む20秒等の観測値とは分離できる。

## ローカル検証

`tools/grading-e2e/check-local-db.mjs --e2e --tutor` を既存の隔離DBハーネス手順で実行する。
Windowsの既存作業用ハーネスからも同じフラグを利用できる。
このハーネスはローカルの架空AI応答を使用する。本番資格情報を渡さない。

- 比較・STEP03・設計相談の3問を3画面サイズで検証する。
- 各結果に `tutor-visible-timing` JSON添付を残す。
- 既存回答を誤認しないよう、送信前の回答件数から次の回答を特定する。
- 空の `AI講師:` 表示だけでは完了としない。
- `controlled-timing` は2回目のAPI応答を1秒遅延させ、計測がその時間を含むことを確認する。
- 添付に質問本文・回答本文・ユーザーID・認証情報を含めない。
- `environment` と `acceptance: not-evaluated` を記録し、ローカルfixtureの速さを本番合格としない。

## 本番受入試験の残件

### 計測レポートの集計

リポジトリ直下から次を実行する。読み取りのみで、ブラウザ・DB・実AIに接続しない。

```powershell
node tools/grading-e2e/summarize-tutor-timing.mjs test-results/tutor-report.json
node --test tools/grading-e2e/summarize-tutor-timing.test.mjs
```

画面サイズ別に試行数・計測数・失敗または欠測数・再試行数・5000ms以下の件数・最大・平均を出力する。
再試行の最良値ではなく初回を採用し、失敗・欠測を母数に残す。平均・最大は測定できた成功分のみで、値がなければnull。
質問・回答・資格情報は集計出力に含めない。制御用の遅延テストは通常サンプルから除外する。
このCLIはローカルfixtureレポート専用で、常にacceptanceをnot-evaluatedとする。本番判定器ではない。

### 実機確認

「10問中9問が回答表示まで5秒以内」の判定には、Canvasからの実LTI起動、事前に固定した架空質問10問、計測環境・負荷条件の記録が必要。
途中の失敗・タイムアウトを母数から除外せず、合格するまで質問を追加しない。
実AI課金と会話ログの作成を伴うため、ローカル検証と分けて実施する。

上のヘルパーはローカルPlaywrightテスト用であり、現在のブラウザ連携にそのまま注入する運用ではない。
本番では、既存LTIセッションを秘密情報として保護し、テスト用ロールCookieを利用しない。
正確な描画時間が必要な場合は、ブラウザ内の送信イベント・描画の計測または画面収録の方法を別途検証する。
その計測手段と成功・失敗の集計が整うまでは、F2の性能受入完了とは報告しない。

初期の計測ヘルパーと集計器はテスト専用。後から追加したTimedReply診断を本番で利用するには、通常のアプリのビルド・反映が必要。DB移行・環境変数変更は不要。

## 2026-09-15 検証結果

- F2 E2E: 39件成功（3画面サイズ、2.5分）。型検査成功。隔離DB停止済み。
- 架空AI応答9件: 120〜223ms。
- 1000ms遅延を与えた2件目: desktop1471ms / monitor1432ms / mobile1477ms。
- 上記は計測の動作確認であり、本番の応答時間・5秒基準の合否ではない。
- 集計器の単体7件成功。保存済みレポートの各画面3件、欠測0件・再試行0件を確認。
- ブラウザ内TimedReply診断の追加後はE2E42件成功。1000ms遅延に対してブラウザ内1057/1041/1041ms、操作側1438/1411/1415msとなり、操作待ち時間から分離できることを確認。
- HTTP失敗で成功診断値が出ないこと、未送信の追加入力で既存の診断値が変わらないこと、コンソールの形式に本文が含まれないことも確認。

## 本番で試した画像観測方式（不採用）

2026-09-15、Canvasのデモ受講生で1問だけ試験した。
送信操作呼出から1973ms時点のスクリーンショットは「考え中」、次の観測で回答画像を取得した時点は20387msだった。
後者にはツール応答と次の観測までの判断時間も混在する。同じ質問のサーバーF2ログは3192ms、outcome=ok。
したがって20387msを実際の表示時間や性能不合格の証拠とはしない。
残り9問は送信せず、この方式を受入判定から除外した。
ブラウザ内で完結する計測または画面収録を用意するまで、10問の性能試験を繰り返さない。
