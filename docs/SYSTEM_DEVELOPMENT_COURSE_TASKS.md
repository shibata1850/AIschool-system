# システム開発コース 開発タスク

登録日：2026年10月6日

ユーザー承認済みの5機能を受講管理システムのシステム開発コース向けに登録する。10月6日、教材改訂より先にこの5機能の実装へ着手した。

関連方針：[BtoB研修の再編計画](BTOB_SELF_PACED_REDESIGN_20261006.md)。各自が別々の自社システムを作り、教材確認後は自分の開発へ進む。機能の割り当て、共通アプリの再現、点数による進行制限は行わない。

## SDC-01 出席管理

- [x] 既存の出席機能とCanvas連携を調査し、重複実装を避ける（旧週次記録は保持、授業回別記録を別管理）。
- [x] 講師が授業回ごとに出席・欠席・遅刻・早退を記録・訂正できるようにする。
- [x] 訂正者と更新時刻を追跡できるようにする。
- [ ] 必要な受講時間の記録方法を運用側と決める。ログイン、教材閲覧、自己申告ステータスから出席時間を自動認定しない。

完了条件：授業回と受講者を取り違えず記録・再表示・訂正でき、権限のない受講者が出席を変更できない。正式な出席時間の算定と修了条件は別途確定する。

## SDC-02 教材への入口

- [x] 既存のBtoBホーム・授業設定を流用できるか調査する。
- [x] 当日の教材を「全員向け要点・必要な人向け・補足」に分けて開けるようにする。分類UIは実装済み。後者2分類の教材URL設定は教材再編時に行う。
- [x] 教材を確認した人が自分の開発へ進み、必要時に教材へ戻れるようにする。
- [x] 小テストや全員の読了待ちを開発開始の必須条件にしない。Eラーニング未提供でも成立させる。

完了条件：本人が当日と過去の必要教材を見つけ、開発ページとの間を行き来できる。教材の未設定を完了と表示しない。全10日分の教材再編と接続する。

## SDC-03 自分の開発ページとシステムリンク

- [x] 本人がシステム名、解決したい困りごとの短い説明、リンクを登録・更新できるようにする。
- [x] 編集用リンクと利用確認用リンクを区別する。どちらも未作成なら無理に必須にしない。
- [ ] 本人と講師・管理者の閲覧を基本とし、別受講者には公開しない。
- [ ] URLの形式・危険なスキームを検証する。パスワードや秘密トークンを登録させない。
- [x] リンク登録によって外部アプリのアクセス権が変わらないことを運用上明確にする（反映記録の「URLと運用」）。

完了条件：本人が保存・再表示・変更でき、講師が対象者のリンクを開ける。他の受講者がURL直接アクセスやAPI経由で取得・変更できない。他社への共有機能は初期範囲に含めない。

## SDC-04 講師への相談と進捗共有

- [x] 今困っている点、次に進めることを短く残せるようにする。長文の提出課題にはしない。
- [x] 「相談したい」を作業ステータスとは別の操作として用意する。
- [x] 講師が相談希望を一覧で把握し、対応済みを記録できるようにする。本人による相談取り下げも扱う。
- [ ] 他社の業務情報を一般の受講者や共有投影へ露出させない。

完了条件：「教材確認中＋相談希望」「開発中＋相談希望」の両方を表せる。相談の重複操作や再読み込みで意図しない依頼が増えず、対応後の状態が本人と講師に反映される。対応済みの操作だけで作業状態を変更しない。

## SDC-05 現在の作業ステータス

- [x] 本人が「教材確認中」「開発中」を選択・変更できるようにする。
- [x] 閲覧タブから推測せず、本人の選択を基本にする。
- [x] 授業回ごとに状態を保持し、次の授業は未設定から始める。未設定は管理上の初期状態で、第三の作業モードではない。
- [x] 講師一覧に受講者名、作業状態、相談希望、最終更新時刻、開発ページへのリンクをまとめる。
- [ ] 通信失敗時は保存成功と表示しない。過去の更新時刻を現在の活動証明として扱わない。

通信ヘルパーの本番コンテナ内確認8件は成功。画面での障害注入は未実施のため、上記のチェックは未完了のままにする。

完了条件：選択が保存され、本人の再表示と講師一覧に反映される。前回の状態を今日の状態として持ち越さない。他人の状態を受講者が更新できない。状態を出席・受講時間・成績へ自動換算しない。

## 実装順と確認

1. 既存機能・DB・権限・授業回の識別方法を棚卸しする。
2. 教材入口と開発ページを整える（SDC-02/03）。
3. ステータス、相談、講師一覧をまとめて整える（SDC-05/04）。
4. 出席管理の不足を補い、作業状態とは独立した運用を確認する（SDC-01）。
5. 本番反映と関連E2Eを架空アカウントで実施し、人による授業運用確認へ渡す。

出席機能の調査は最初に行う。画面の実装順は、既存機能の不足と依存関係に応じて調整する。E2Eは保存・再読込・入力不正・権限・授業回切替・通信失敗を対象にする。本番での破壊的テストや実受講者データの使用は行わない。

講師の閲覧は既存の全コース確認方針と実際の権限を照合する。受講者間の隔離は維持する。学生向け等の既存機能と履歴は削除せず、システム開発コースの主画面から分離する。

## 今回含めない機能

- 独自のAIシステム改善提案。まずBASE44側を利用し、必要性を見て別タスクにする。
- 小テスト、誤答分析、点数による進行制御の追加実装。
- 学習時間の自動認定、読了による修了認定、リンク先アプリの自動公開。
- 開発ステータスの自動推測、企業別Quest動画の自動制作。
