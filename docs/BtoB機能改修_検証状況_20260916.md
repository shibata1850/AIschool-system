## ローカル検証

専用一時DBハーネスは `tools/training/check-local-db.mjs`。
リポジトリ内に実環境の `.env` 系ファイルがある場合は停止する。
接続先は新規作成したlocalhostの一時DBのみ。認証情報は毎回生成し、出力しない。
完了時はDBを停止する。一時データディレクトリは調査用に残し、自動削除しない。

cmdでの実行例（リポジトリ直下）:

```cmd
set "TRAINING_PG_BIN=C:\path\to\postgresql\bin"
node tools/training/check-local-db.mjs
node tools/training/check-local-db.mjs --all
node tools/training/check-local-db.mjs --e2e
node tools/training/check-local-db.mjs --e2e --production
node tools/training/check-local-db.mjs --navigation
node tools/training/check-local-db.mjs --legacy-e2e
```

`TRAINING_PG_BIN` はローカルPostgreSQLの `initdb` と `pg_ctl` があるフォルダ。
既定は新機能の単体・DBテスト、`--all` は全単体テスト、`--e2e` は新機能のブラウザ検証。
`--navigation` は既存メニュー導線のみ。テストプロセス内で開発用Cookieロールを有効にするが、
設定ファイルは変更せず、リセットAPIも使用しない。`--e2e` との同時指定は不可。
`--e2e --production` はビルド後に `next start` で新機能を検証する。本番サーバーへの配置ではない。
`--legacy-e2e` は既存標準E2Eを隔離DBで実行する。ローカル限定でリセットAPIを使用する。
最初に `playwright.training-signed.config.ts` で旧デバイス9件・退会データ伝播1件・外部到達度削除1件・週次生成9件・保持期限6件・デバイス無変更回帰1件を
2画面条件の署名付き認証（計54件）で実行し、成功後に旧Cookie認証を前提とする残り572件を実行する。
二段階目での対象ケース除外は重複実行を避けるためであり、全体ハーネスでは省略されない。
署名付き段階はリセットAPIを使用しない。退会処理の対象も新規一時DBの架空レコードだけ。
最初の失敗で停止。専用の模擬サーバーを必要とするAI応答・コース分離のテストは別構成のため対象外。
